## 为什么需要这张卡

本项目是**非托管钱包**，且全部开发由一人完成（86/86 提交）。这带来一个其他风险都无法比拟的失效模式：

> **如果我不再能接触这些设备，会发生什么？**

具体地：

1. **用户资产**不受影响 —— 私钥只在用户自己的设备上，这是非托管架构的好处，也是本项目最重要的安全属性。
2. **平台费收入会停止** —— `VITE_SWAP_FEE_WALLET` 指向的收款地址若无法动用，抽成将永久锁死。
3. **托管服务会到期** —— 域名、Cloudflare Pages、API Key。**域名过期不需要任何人攻击你，只需要你消失 60 天。**
4. **代码可能丢失** —— GitHub 是托管平台，**不是备份**。

按 `ENGINEERING-STANDARDS.md` §0.3 红线 7 的口径：**未验证可恢复的备份，视为没有备份**。一个只有我能取用的凭据，在被测场景（我失联）下同样未经验证 —— 按这个标准，它等于不存在。

## 6. 最小可运维状态

本项目**没有后端**，所以「继续活着」的门槛很低：

| 项 | 现状 | 满足 |
|---|---|---|
| 用户资产是否依赖我 | **不依赖** —— 非托管，私钥在用户设备 | ✅ |
| 是否需要服务器维持运行 | 不需要 —— Cloudflare Pages 静态托管 | ✅ |
| 服务端是否持有用户数据 | 不持有 | ✅ |
| 依赖的公共 RPC 是否需我维护 | 不需要（公共节点 + 用户可自配） | ✅ |
| 平台费归集是否自动 | **取决于收款地址是否可达** | `<是/否>` |
| 域名到期后用户能否继续用 | **能** —— 已安装的扩展与 App 不依赖域名 | ✅ |
| 新用户能否安装 | 依赖域名/商店 | `<是/否>` |

**结论**：本项目的**抗中断能力天然很强**。真正的暴露面只有两处 —— **平台费收款私钥**与**凭据生命周期**。

| 触发条件 | 谁能叫停 | 步骤 |
|---|---|---|
| 发现私钥/助记词泄露或疑似泄露 | | `<1. 立即轮换 API Key　2. 公告　3. ...>` |

**一键全停步骤**（必须能照着做，不需要理解项目）：
```
1. <Cloudflare Pages：暂停/删除部署>
2. <域名：注册商处锁定或暂停解析>
3. <GitHub：仓库转 private 或 archive>
```

**停止后用户资产处置**：**无需处置** —— 非托管钱包中用户资产始终在用户自己手上。这是本架构最重要的安全属性。

> 创建发布 keystore 时，**必须**同步：① 离线备份 ② 纳入本卡第 2 章 ③ 明确丢失后的后果（Android 应用**无法更新**，只能换包名重发）。
